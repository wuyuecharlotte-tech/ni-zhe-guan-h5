---
name: cloudSave-save
description: 将用户进度、草稿、选择或个人设置保存到指定云存档位；编号为 1–5，同编号完整覆盖。
---

# Usage

- JS Path: `window.ColorboxAI.cloudSave.save(params)`

# Constraints

- 新接入首选 save/load；已有 getValue/setValue 应用可继续使用原接口，不强制迁移。决定切换时不能只替换方法名，应先处理旧 key 数据；用法与迁移见 cloud-save/SKILL.md
- 结合游戏或应用实际功能选择保存时机，接入云存档不代表需要自动保存；无恢复需求不保存，点击保存、确认步骤、完成关卡或检查点已足够时只按这些节点保存；仅长篇草稿、持续创作或需保护中途进度等功能按需启用持续自动保存，不扩展到其他功能，用户未确认的编辑不自动覆盖约定手动保存的正式存档
- 固定存档编号用途，读写使用相同编号；建议最多使用三个存档位，一起保存和恢复的小字段放同一对象，仅保存时机或加载需求独立时才拆分；同编号完整替换，不合并对象字段，共用对象提交完整有效快照，多个存档位保存不保证一起成功
- 按白名单只存无法可靠重建的用户内容、进度、选择和设置；已有数据优先存稳定 ID 及必要关系或顺序，详情恢复时重新获取，名称不能替代稳定 ID；必要正文完整保留。数据取舍与场景示例见 cloud-save/SKILL.md
- 不存整个 state/store、接口响应、派生值、静态配置、临时 UI 状态、日志、资源二进制或 Base64；资源成功上传后只存可恢复引用，历史限定范围，不保存 token、密码、Cookie
- 只在必需字段变化时保存，提交前序列化一次并复用；同一用户/应用/活动/存档位可跳过与上次成功值相同的内容，失败不更新成功记录，成功后更新或失效读取缓存；不在输入、渲染或逐帧回调中反复序列化和深拷贝
- 仅在启用持续自动保存时合并连续变化，同一存档位至少间隔 3 秒并按可接受的进度损失设最长等待；不是每 3 秒定时保存，无变化不写，仅按节点保存无需这套调度。手动保存防重复，手动或明确业务节点不必等待该间隔；同一存档位不重叠写，旧请求成功不能清掉新变化，不只依赖关闭时保存
- 已启用自动保存且需要恢复时，成功读取、解析和校验前暂停自动写回；普通手动保存不要求先读。卸载或切换用户/应用/活动/存档位时清理定时器、监听、缓存及待写任务，忽略旧结果
- 只有 code === 200 才提示已保存；失败提示并保留内容，暂停该失败操作的自动提交，不由定时器或队列立即重发、不无限重试。413 先去冗余，仍超限不能截断必要内容；2MiB 是 UTF-8 字节上限而非目标，验证体积、请求次数和序列化耗时
- 超时或网络中断不代表云端未写入，底层请求可能仍在执行；暂停自动写并保留提交快照及新编辑，不立即发起可能被旧请求覆盖的新写入。没有删除接口，清空需按业务约定保存空状态，空字符串不等于无存档；重置及提交后清理须处理旧待写和在途请求，不能清掉新编辑。细则见 cloud-save/SKILL.md

# Parameters

| 参数名 | 类型 | 是否必填 | 说明 |
| --- | --- | --- | --- |
| slot | integer | 是 | 存档编号，只接受 1–5 的整数；固定用途，建议每个应用最多使用三个存档位 |
| value | string | 是 | 恢复必需的数据字符串；对象按需 JSON.stringify，最多 2MiB UTF-8 bytes |

# Returns

- Type: `Promise<Response>`

### Response Properties

| 属性名 | 类型 | 是否必填 | 说明 |
| --- | --- | --- | --- |
| code | number | 是 | 成功为 200，失败时为错误码 |
| message | string | 是 | 结果说明 |

# Examples

```javascript
window.ColorboxAI.cloudSave.save({ slot: 1, value: JSON.stringify({ levelId: 3 }) }).then(res => { if (res.code !== 200) throw new Error(res.message || "保存失败"); console.log("保存成功"); }).catch(error => console.warn(error.message));
```
