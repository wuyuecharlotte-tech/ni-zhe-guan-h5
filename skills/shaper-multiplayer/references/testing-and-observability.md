# 测试与可观测性

## 测试分层

| 层 | 证明什么 | 测试边界 |
| --- | --- | --- |
| Domain 单元 | 规则、状态转换、不变量、确定性结果 | 纯函数和系统 |
| Room 集成 | 准入、命令路由、状态投影、重连、清理（重连四类路径的断言点见 [断线与刷新重连](reconnection.md)） | Room 加测试客户端 |
| 协议契约 | 公开/私有字段、错误码、payload 兼容性 | 共享协议 fixture |
| 场景 | 一段跨房间和阶段的短玩家旅程 | 带假时钟的测试夹具 |
| 负载/浸泡 | 每 tick 工作量、内存、队列行为、重连风暴 | 一次性环境 |

对那种通过 socket 调试会非常昂贵的规则，先写 domain 测试。截止时间用假时钟，结果用带 seed 的随机源。保持集成场景简短，并写明它证明的不变量。

## 可观测性字段

发出结构化事件，包含：

- `roomId`、`matchId`，以及请求或命令的关联 ID；
- 房间模式和协议版本；
- 玩家数量、阶段，以及服务端 tick 或回合号；
- 命令名、校验结果和稳定错误码；
- 模拟、序列化、持久化和外部调用的耗时。

不要记录认证 token、私有手牌、隐藏目标，或可能包含用户内容的完整入站 payload。

## 有用的指标

- 按模式和地区统计的活跃房间数；
- 准入、加入、离开、重连和认输的计数；
- 重连成功/失败、宽限期超时和房间销毁的计数与比率（口径见 [断线与刷新重连](reconnection.md)）；
- 按原因分类的命令拒绝率；
- 模拟耗时和 tick 迟到情况；
- 状态 payload 大小和每房间的出站消息量；
- 持久化延迟和幂等冲突；
- 房间销毁时长和清理失败。

对持续的 tick 迟到、上升的拒绝率或重连失败、卡住的房间和持久化错误告警。单条慢命令应能通过其关联 ID 诊断，而不需要全局打开 verbose 日志。

## 重放与事故分析

对竞技类或经济敏感的游戏，按有界保留策略记录已接受的命令 ID 和 domain 事实。重放应消费事实或确定性输入，而不是信任客户端状态。把隐私和删除要求纳入保留策略的决策。
