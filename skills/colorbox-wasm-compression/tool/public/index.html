压缩文件如何用于你的项目？

在平台中使用：直接使用压缩后的文件即可，平台会自动处理加载所需的配置，无需额外操作。

本地开发：同样使用压缩后的文件，按下面的示例配置本地开发服务后，就能直接引用压缩文件的地址，无需手动解压。

Vite 配置示例：将 module.wasm.br 放入 public 目录，在现有 vite.config.js / vite.config.ts 的 plugins 中合并以下插件，保留项目其他配置，然后重启开发服务。示例同时支持 module.wasm.gz 和 module.wasm.zst；文件名不同时，同步修改匹配规则和读取路径。

import { readFile } from 'node:fs/promises';
import { join } from 'node:path';
import { defineConfig } from 'vite';

export default defineConfig({
  plugins: [{
    name: 'serve-compressed-wasm',
    configureServer(server) {
      server.middlewares.use(async (req, res, next) => {
        const path = new URL(req.url || '/', 'http://localhost').pathname;
        const match = /^\/module\.wasm\.(br|gz|zst)$/.exec(path);
        if (!match || !['GET', 'HEAD'].includes(req.method || 'GET')) return next();

        try {
          const bytes = await readFile(join(
            server.config.publicDir, `module.wasm.${match[1]}`
          ));
          const encoding = match[1] === 'gz' ? 'gzip'
            : match[1] === 'zst' ? 'zstd' : 'br';
          res.setHeader('Content-Type', 'application/wasm');
          res.setHeader('Content-Encoding', encoding);
          res.setHeader('Content-Length', bytes.length);
          res.setHeader('Cache-Control', 'no-store');
          res.end(req.method === 'HEAD' ? undefined : bytes);
        } catch (error) {
          next(error);
        }
      });
    },
  }],
});

加载示例：直接请求带压缩后缀的地址，浏览器会根据响应头解压，再交给 WebAssembly。下面的 imports 沿用项目已有的模块导入配置；如使用引擎或工具链生成的 JS 加载器，只需将它的 WASM 路径指向 /module.wasm.br，保留原有初始化方式和配套 JS 文件。

// imports 使用项目已有配置，不需要添加解压逻辑。
const { instance } = await WebAssembly.instantiateStreaming(
  fetch('/module.wasm.br'),
  imports
);
// 继续通过 instance.exports 使用模块。

如何确认配置生效：打开浏览器 Network，检查压缩文件请求返回 200，Content-Type 为 application/wasm，Content-Encoding 与文件格式一致（.br → br、.gz → gzip、.zst → zstd）。浏览器需支持对应编码；zstd 不兼容时可改用 gzip 压缩地址。示例按不同地址提供不同编码，无需协商；若同一地址按 Accept-Encoding 返回不同版本，还需设置 Vary: Accept-Encoding。以上插件仅用于 Vite 开发服务，vite preview 或其他静态服务需单独配置。
