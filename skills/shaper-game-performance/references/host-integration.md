# 虎扑总包适配

本页把性能工作接到总包已有能力；不复制 SDK、平台操作、云资源模板或状态机。安装位置是 `skills/shaper-game-performance/`，本页的外部链接指向同级技能。通用模块可独立更新，平台差异在本页收敛。

## 先区分任务上下文

| 当前上下文 | 性能工作如何进入 |
|---|---|
| 本地离线游戏或未上传的开发项目 | 直接走前端模块的启动/采样流程；无需加载云服务、Debug 登录或 runbook |
| 已上传页面的独立排障 | 从 [shaper-debug](../../shaper-debug/SKILL.md) 获取/复用有效授权会话和日志；不因此重新发起 H5 交付 |
| 已有接口或数据库的专项诊断 | 先用已有代码、日志和计划定位；实际访问/更改平台资源才加载对应 CloudBase 入口 |
| 交付中的性能工作 | 沿用总包 AGENTS.md 与 [runbook](../../runbook/PROCESS.md) 当前阶段；静态 security-review 内不运行页面，运行验证放在阶段允许的位置，不另建门禁或改写后台审查结果 |

模块要求“运行项目”时，已上传页面可使用实际预览环境，不强制再启动一套本地服务。只有本地代码修复或隔离实验确有需要，才启动对应服务；本地数据与线上/预览数据分别标注。

## 预览受阻时的验证路径

本地服务、独立 Playwright、浏览器或登录任一环节失败时，按下列顺序选择仍可行的验证；单个工具失败只限制该路径。

1. 保存具体错误，盘点现有浏览器/UI 工具、项目身份与已上传预览。Shaper 项目存在已上传版本或有效预览地址时，主动读取并使用 [shaper-debug](../../shaper-debug/SKILL.md)，复用其 MCP 优先/脚本回退、模拟登录、actor 与 CLS 日志流程；不要求用户再次提出调试。未上传且无平台预览的离线项目继续本地构建、静态与子模块验证。
2. 按 shaper-debug 获取平台实际返回的完整授权入口，在可用浏览器中完成真实点击/触摸，检查目标状态、接口业务结果和报错。无浏览器时复用有效入口请开发者真机复现，并查询同一排查编号、操作时间/trace 的日志；可查询已有日志时先查询，不把日志验证等同于页面交互已通过。没有身份/授权/日志能力时记录具体缺口，继续其他不依赖它们的验证。
3. 核对预览所属项目、上传版本/构建哈希及当前加载资源。平台默认取最新上传版，不保证是本地候选。对照记录 `基线构建 → 候选构建 → 实际预览版本 → 场景/操作 → 可见结果/请求/日志`；版本不一致的证据只用于所测版本，候选保留待验证。需要上传候选时沿用原流程和已有授权；未获授权则先交付可审查代码与验证结果，不为调试自行发布或部署。
4. 在同场景、同身份/数据与可比环境中复现基线和候选；重新上传的候选使用新的平台入口。记录请求数、耗时、失败与业务状态；仅有页面/日志证据时不推断 FPS、GPU、堆峰值或线上吞吐。日志为空、查询部分失败或未确认数据上报时，沿用 shaper-debug 的延迟/完整性检查，标记待验证。
5. 页面仍不可用时，完成可运行的后端源码实验、接口隔离测试、构建和资源检查；逐项写明页面交互、日志、功能与性能的通过/失败/未测状态。最终验证范围以实际证据为准。

Debug 模拟身份仍会访问真实业务服务。沿用项目已有测试身份和数据操作授权；请求脚本/业务函数直调只能作为局部诊断，页面验收仍执行实际交互。授权链接与凭据只保存在 shaper-debug 的私有上下文，报告保存脱敏编号与证据位置。

## 按实际动作选择平台能力

| 要做的事 | 使用现有入口 | 本技能负责的部分 |
|---|---|---|
| 查询或修改云函数、网关、PG、云环境 | [act-cloudbase](../../act-cloudbase/SKILL.md)，其入口再选领域参考 | 给出待验证假设、调用/资源预算与回归命题 |
| 修改活动页面云请求 | [colorbox-cloud-request](../../colorbox-cloud-request/SKILL.md) | 减少重复触发、测响应处理，沿用 SDK 的身份与业务结果契约 |
| 复现已上传页面、登录、多用户、查远程日志 | [shaper-debug](../../shaper-debug/SKILL.md) | 将已有会话/trace 证据与本地帧/资源观测关联 |
| 修改 Room tick、消息、重连、准入或持久化 | [shaper-multiplayer](../../shaper-multiplayer/SKILL.md) | 判断积压、延迟和资源成本，验证同步与权威状态 |
| 确需调整或发布 Room 云运行 | [game-room-deploy](../../act-cloudbase/references/game-room-deploy.md) | 提供候选改动和验证条件，复用原部署与版本确认流程 |

活动 API 与 Room 的协议、鉴权和网关规则分别沿用各自入口，不能把活动 API 的实现套到 Room。项目原有公共组件继续负责平台操作；性能优化不创建第二套资源、网络通道、鉴权或日志上报服务。

## 浏览器采样的衔接

### 本地可重复入口

可使用前端模块的 [Playwright 驱动](../modules/web-game-performance/scripts/run_browser_scenario.mjs)和[工具说明](../modules/web-game-performance/references/automation-tools.md)。它每轮创建新的 browser context，访问配置中的同一个 `url`，再执行 setup。它不会自动继承现有页面登录，也不实现 Shaper 授权协议。现有驱动只设置 viewport/DPR，未设置 mobile UA/touch；窄屏不等于移动端，模拟设备也不等于真机性能。按实际能力标注环境。

### Shaper 已授权页面

1. 按 shaper-debug 使用实际预览所属项目、actor 和浏览器上下文，先确认业务状态正确，再开始性能采样。预览项目可能不同于技能包绑定项目，不混用其环境证据。
2. 在工具和页面规则允许时，在这个已授权上下文中加载有界探针，按真实指针/触摸操作采样；按平台能力取得的 traceId/debugRunId 关联日志。本地业务 hook 可辅助定位，但不能代替平台要求的真实交互验收。
3. 同一授权上下文中重复场景时，重置业务场景而不盲目清空登录；在记录中标明这是同会话重放，不当作 fresh-context 或真正冷启动。若场景无法安全重置，选隔离测试身份/场景或记录不可重复的限制，不重复发奖凑采样轮次。
4. 需要新的浏览器上下文时，由 shaper-debug 按需取得新的有效入口。原驱动固定 URL，不支持逐轮刷新入口；**不要直接把一次性 qrUrl 填进它的配置运行多轮**。优先现有平台浏览器会话；确需自动化接合时单独适配平台能力并验证，不在本技能重写登录。
5. 采样报告仅保存脱敏关联编号和证据位置。**不要把授权链接、token 或 credentials 放入驱动配置/原始指标/报告**：原驱动在采样前失败时可能将完整配置写入失败记录。一次性入口仍只由平台私有调试上下文管理，不将 debug-context.json 原样复制进性能产物。

探针不发请求，但“可注入”仍由实际工具与页面策略决定；不放宽 CSP/CORS 或改正式鉴权以便采样。不具备注入/导出能力时复用现有 profiler、调试数据或人工观测，准确标注缺口。CLS 暂无结果或 partial 不能解释为没有错误。

## 平台规范与性能结论

身份、发布、资源归属和业务契约沿用当前项目规范；读取平台文档不是部署或业务写入授权。测试是否触及真实数据、发布是否已授权，由原任务与平台流程决定。

缓存时长、索引建议、实例默认值和理论收益不能充当实测。按通用工程模块验证真实执行计划、回源与数据分布。遇到规范与观测或业务语义矛盾时，记录对应条目、证据和影响，先完成不冲突的工作；需要调整平台约定时在其原维护位置提出最小变更，不复制一份新平台规则，也不默默绕过约束。

部署确认沿用[主入口的交付闭环](../SKILL.md#主动修改交付代码再确认部署)：先主动完成已授权的本地优化、验证和完整候选交付，再向用户确认具体版本、目标环境/函数与部署范围。用户要求“先不要部署”时，shaper-debug 验证需求也不构成候选上传发布或服务部署授权；复用现有预览证据并标明版本差异，继续不受阻的本地验证。已有明确覆盖当前候选的授权不重复索取；等待确认时不调用平台写入/部署操作。

性能结论独立记录：目标操作、资源和正确性是否通过。平台发布结果仍由原流程产出；两者可以互相引用，不能互相替代。
