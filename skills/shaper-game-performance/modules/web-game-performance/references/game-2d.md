# 2D 游戏专项

适用于 Canvas2D、WebGL/WebGPU 2D renderer、Sprite、Tilemap、2D 骨骼与 UI 密集游戏。先区分 CPU 绘制、GPU 像素负载、纹理上传和玩法模拟。

| ID / 细分维度 | 诊断信号 | 最佳实践 | 具体优化方案 | 验证与取舍 |
|---|---|---|---|---|
| D01 合批与状态 | sprite 少但 batch 多 | 找真实断批原因 | 用帧捕获定位 texture/blend/shader/mask/render target/顺序切换；兼容状态相邻绘制 | batch、提交 CPU、视觉层级；透明对象不能为排序而画错 |
| D02 图集策略 | 多纹理切换、图集常驻巨大 | 按同时使用和生命周期分组 | UI/角色/关卡独立 atlas，适度页尺寸，边缘 extrusion/padding；多纹理 batch 依引擎能力 | DrawCall、浪费率、驻留；不把所有关卡合成 8192 大图 |
| D03 透明过绘 | 爆炸/雾/辉光掉帧，draw 不高 | 控制屏幕覆盖与叠层 | 裁掉透明边、减粒子尺寸/寿命/重叠；降低特效 RT 分辨率，适度用不透明背景 | renderScale/特效开关 A/B、GPU；减少对象数但扩大面积可能更慢 |
| D04 Sprite 几何 | 大透明四边形覆盖屏幕 | 用合适裁剪和网格 | trim atlas、紧致 mesh、合理 anchor；别为每个小 sprite 过度增加三角形 | GPU 与顶点成本、旋转/命中框；图形裁剪不改变碰撞语义 |
| D05 Canvas 静态绘制 | 大量重复 draw/path/text | 静态结果只在变更时重绘 | 离屏缓存背景/复杂图形，有限图层，预渲染重复 primitive；优先引擎现有机制 | CPU/paint、缓存内存；每帧更新内容不适合缓存 |
| D06 Canvas 脏矩形 | 局部变化却重绘整屏 | 仅在可正确合成时局部重绘 | 合并脏区、记录新旧 bounds，超面积阈值退回全绘 | 拖影、透明混合、相机移动；全屏滚动时全绘常更划算 |
| D07 Canvas 读回 | getImageData/readback 尖峰 | 绘制与像素分析隔离 | 低频低分辨率分析 canvas，避免读写交替；willReadFrequently 仅读回密集场景实验 | 绘制/读回两端都测；该 hint 可能使 GPU 绘制退化 |
| D08 Canvas 状态与路径 | 大量 save/restore/clip/shadow | 降低不必要状态变化 | 合并相同笔刷，缓存 Path2D，减少复杂 clip 和动态 shadowBlur；opaque 场景可评估 alpha:false | CPU/画质、混合正确；不是所有 canvas 都可禁透明 |
| D09 Tilemap 渲染 | 大地图绘制不可见瓦片 | 可见块渲染与资源分块 | 相机可见 tile range、chunk mesh/cache、滚动增量加载；动态 tile 局部更新 | 快速移动边缘、draw/CPU；块过大损害剔除，过小增加提交 |
| D10 Tilemap 碰撞 | 每 tile collider/重建卡顿 | 静态碰撞独立于美术 tile | 合并相邻实体边界、空间索引、只更新变更区域；流式块管理碰撞加载 | 边界/高速穿透；不能只加载屏内碰撞导致屏外逻辑错误 |
| D11 2D 骨骼 | Spine/DragonBones pose/mesh 热 | 骨骼、网格、采样按画面贡献分级 | 减骨骼与 deform 顶点，减少约束/裁剪，远处降采样，适合者烘焙序列帧 | 动画事件/碰撞框、CPU/显存；烘焙增加纹理驻留 |
| D12 序列帧 | 帧图纹理大、首次播放卡 | 帧率/尺寸匹配展示 | 去重复帧、裁边、分组 atlas、预热关键片段；必要时骨骼替换大序列 | 压缩/解码/上传/显存；不能只比较下载体积 |
| D13 粒子渲染 | 粒子 draw 多或 fill 高 | batch 与像素预算同时控制 | 同纹理/混合粒子合批，instance/引擎专用 particle 容器；特效分档与屏幕面积预算 | 最大爆炸而非空场景；GPU 粒子不消除过绘 |
| D14 粒子分配/池 | 战斗生成回收尖峰 | 有界活跃和复用容量 | 预热实测常见量，限制 burst，缓增扩容；回收 reset、取消 timer，空闲池可缩 | update/GC、空闲池峰值；预热别把启动/OOM 转移恶化 |
| D15 文字与字形 | HP/伤害数字频繁栅格化 | 固定字集与动态文本分开 | 数字用 bitmap/SDF atlas，文本变更才重建；控制字形 atlas 页和字体回退 | 中文/emoji/复杂字形、DPR 清晰度；SDF 有 shader 与内存成本 |
| D16 字体加载 | 首次打开 UI 长帧/跳字 | 字体按字符范围/使用时机组织 | 合法字体子集、首局关键字预热、异步加载回退，字形缓存限量 | 首次文本、弱网、缺字；不随意破坏多语言覆盖 |
| D17 UI 树与布局 | UI resize/开面板长帧 | 静动分离、dirty 更新 | 深层布局扁平化，列表复用/虚拟化，隐藏页停更新，动静 canvas/batch 分开 | UI profiler、正确布局；新增图层也增加合成/显存 |
| D18 mask/滤镜/混合 | 一个容器新增多个 offscreen pass | 局部、小尺寸、低频 | 矩形裁剪用适合的 scissor，复用稳定缓存；blur/displacement 局部 RT/降采样 | pass、RT 字节、边缘画质；旋转/嵌套 mask 不可一概替换 |
| D19 场景缓存与 RenderTexture | cache 后显存高、动态仍卡 | 只缓存高重用低变化子树 | 在内容变化时重建，尺寸按需求，释放不再使用 RT；记录缓存收益 | 每帧重建次数、内存、draw；缓存并非零成本 |
| D20 视口、排序与命中 | 全节点排序/全 UI hit test | 可见集、交互集独立管理 | 静态层级排序一次，局部 dirty z-order；非交互容器关闭命中遍历，空间索引 | 遮挡顺序、点击穿透；不可把显示剔除当作逻辑休眠 |
| D21 像素画与缩放 | DPR 大、画面模糊或 GPU 高 | 内部渲染分辨率匹配美术 | 整数缩放、nearest 采样、逻辑与物理像素分离，避免不必要大画布 | 细线/字体/旋转效果；pixel rounding 不适合所有平滑运动 |

## 2D 卡顿定位例

症状：平均 58 FPS、DrawCall 35，爆炸时 P99 72ms。不能据此判定「合批已经够好，只需加对象池」。

1. 固定爆炸位置、粒子种子、相机和画质，记录首次与预热后爆炸。
2. trace 将长帧与粒子创建/GC、纹理上传、shader 编译对应；有条件记录 GPU query。
3. 分别只降粒子数、屏幕覆盖面积、renderScale。后两者明显改善时优先过绘/fill/shader；创建/GC 占主导时优先分配和有界池。
4. 方案须列出效果质量变化、CPU/GPU/内存之间的交换；同一爆炸脚本复测并检查命中、音频和输入响应。
