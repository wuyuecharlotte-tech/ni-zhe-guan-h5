# 测量与诊断

## 目录

基线与预算；指标口径；工具与观测；瓶颈实验；场景矩阵；常见误判。

需要实际跑项目时先读 [执行流程](execution-workflow.md)，用 [自动化工具](automation-tools.md) 或已有平台工具保存逐轮原始数据。体验看板的打开速度、操作响应、流畅项、异常错误率和白屏率的定义、分子分母与映射见 [体验指标](experience-metrics.md)，不能将平台名称直接等同本地指标。

## 1. 基线与预算

先记录构建标识、引擎/浏览器/系统版本、渲染后端、设备型号、屏幕刷新率、CSS 尺寸、drawing buffer 尺寸、DPR、渲染比例、画质、供电与温度状态、网络/缓存条件。默认用发布构建评价结果，调试构建用于定位；不要拿两种构建直接对比。

- 帧预算 `B = 1000 / targetFPS` ms；30/60/120 FPS 对应约 33.33/16.67/8.33 ms。这是总呈现节奏预算，主线程不能独占全部时间。
- 预算沿用项目实际目标，不额外强加预算配置文件。项目未定义时，可用标注假设的探索性目标开展测量；附带脚本的60FPS默认值是运行默认，不代表项目已接受的验收目标。
- CPU 提交、GPU 执行与呈现可能流水重叠，不把 CPU+GPU 时间机械相加。分别记录主线程忙碌时间、GPU 工作时间和呈现间隔。
- 预算按设备档位与场景确定：允许的 P95/P99 帧间隔、超预算率、连续卡顿、启动可玩耗时、峰值/稳态内存、网络积压；无实测前只给建议区间，不写成官方门槛。
- 冷启动、缓存命中的热启动、shader/纹理首次使用、预热后的稳态分别测量。预热不能掩盖首次战斗卡顿。
- 同一随机种子、敌人数、镜头路径、特效组合；改变一个变量后复测。每组建议至少 3 次，记录波动；昂贵实验可先短采样筛选，再对候选项完整复测。

## 2. 指标口径

| 指标 | 正确用途与限制 |
|---|---|
| FPS、帧间隔 P50/P95/P99、最大间隔 | FPS 用总帧数/总时间；百分位取原始间隔，不对 FPS 百分位求倒数。每个场景单独统计，注明窗口与样本量 |
| 超预算帧率、卡顿事件 | `间隔 > B + 容差` 的比例；容差由刷新节奏与测量精度确定。记录超过 2B 的次数、连续长度及时间戳；不要用恰好 16.67ms 的硬比较制造噪声 |
| rAF 间隔 | 近似观察浏览器回调节奏，受调度、后台限频、刷新率影响；不是 JS 执行时长、GPU 时间或可靠的实际屏幕呈现证据 |
| CPU 分阶段耗时 | input/update/physics/AI/animation/cull/render-submit/UI/decode/upload，User Timing 或引擎 profiler。采样日志不能变成新的逐帧负担 |
| GPU 时间 | WebGL timer query 扩展可用时异步读取已完成结果、过滤 disjoint；WebGPU timestamp-query 要先检测 feature/权限和精度限制。不可用时用帧捕获、实验、平台 profiler，标注间接证据 |
| DrawCall / batch / pass / state switch | 统计所有 camera、shadow、depth、reflection、post、UI pass，注明计数器重置规则。数值少仍可能 fragment bound |
| 三角形、顶点、instance、骨骼、粒子 | 同时看可见量、每 pass 处理量及 CPU/GPU 耗时，资源文件面数不等于每帧提交量 |
| JS heap / WASM heap / ArrayBuffer | 不等于进程总内存；typed array 常含外部 backing store。API 可能仅浏览器专有或需隔离条件，不可跨浏览器直接比较 |
| 纹理、buffer、RT 数量与估算字节 | 是资源账本或估算，不是已测显存。驱动副本、对齐、压缩、MSAA、深度附件会改变实际使用 |
| 进程/宿主内存、OOM/异常退出 | 用系统、浏览器或宿主工具，标清采样口径；进程可共享，不能拿 JS heap 代替，也不把所有异常退出归因 OOM |
| 输入延迟 | 分开输入到逻辑生效、到提交、到实际呈现；真实 input-to-photon 需要平台工具/高速摄影。INP 可补充 DOM UI，不代表 Canvas 游戏完整输入体验 |
| 可玩耗时 | 定义为首场景资源齐备、首帧显示并可响应有效输入；LCP/FCP 只能描述宿主页面，不能代替首局可玩 |
| 网络 | RTT、jitter、loss、收发 bytes/s、包率、send queue、快照年龄和主线程解包时间，区分网络慢与本地卡顿 |

## 3. 工具与低开销观测

- 浏览器 Performance trace：主线程、任务、GC、帧、布局、脚本、资源时间线；Memory heap snapshot / allocation sampling 定位保留链。开发工具本身可能保留 console 对象并放大开销。
- User Timing 的 mark/measure 先采样，再消费或导出，及时清理本工具创建的 entries；不要逐帧无界累积或清除其他模块的条目。观察回调也要有界。瞬时 `1000 / 单帧间隔` 不能代表窗口平均 FPS；`performance.memory` 若存在也只是非标准的 JS heap 口径，不是总内存或通用 OOM 阈值。
- Spector.js 或同类 WebGL 帧捕获工具：看 pass、实际 draw、纹理/材质切换、重复提交；先确认当前后端受支持。WebGPU 不套用 WebGL hook。
- 引擎 profiler / inspector：节点树、UI 树、资源引用、渲染统计、物理与动画时间。依据项目实际版本选 API。
- 移动真机远程调试、系统/宿主内存工具；模拟 CPU 限速只用于定位，不代替手机热状态和 GPU 带宽测量。
- 借鉴 log-viewer：把日志、性能曲线、场景节点、UI 节点、资源 ID 和 `sceneId/frameId` 关联。原始数据有界保存，示例 600 帧在 60 FPS 下约 10 秒，不能当成恒定 10 秒窗口；需要固定时长则按时间淘汰并设硬容量。
- 诊断 UI 低频刷新，如 2–5Hz；采样环形缓冲、故障前后窗口、错误去重与限流。隐藏/关闭面板后停止树遍历、纹理缩略图生成、订阅和昂贵序列化。
- 面板开/关做 A/B；面板会增加 draw、布局、分配和 GPU 工作，不把简单减去固定 DrawCall 当作完整开销校正。
- 线上只记录必要的聚合指标、版本、设备档位、场景与错误类别，限制上报量和队列；不上传完整聊天、凭据、个人信息或无界运行日志。

## 4. 用实验分离瓶颈

| 观察 | 最小区分实验 | 下一步 / 注意 |
|---|---|---|
| GPU 时间高，分辨率下降明显改善 | 只改 renderScale，保持物体与模拟数量相同 | 排查 fill rate、过绘、shader、后处理及带宽；CPU 提交也可能变化，需交叉证据 |
| CPU update/physics 热点明显 | 固定渲染负载，仅关闭特定模拟子系统作诊断 | 检查数据访问、候选对、寻路、调度；诊断开关不等于可上线玩法变更 |
| render-submit 高，GPU 尚有余量 | 减少材质状态切换，测试实例化/局部合批 | 检查批次破坏点与剔除粒度，不直接全场景合并 |
| 每次首次爆炸或镜头转向卡顿 | 预热对应纹理/shader/粒子后重放 | 检查编译、decode、GPU upload、pipeline、池扩容；预热也有启动/内存成本 |
| 周期性锯齿与 GC 长帧重合 | allocation sampling，隔离热点分配 | 减少临时数组/向量/字符串、适度复用；不能直接每帧强制 GC |
| heap 回落但进程继续上涨 | 场景往返，记录纹理/RT/audio/WASM/原生计数 | 检查 GPU/原生驻留、驱动缓存与资源保留；观察稳定平台而非只看单次快照 |
| 开始流畅，运行数分钟掉帧 | 同画质连续运行并对照冷机/热机 | 检查温控、功耗、资源增长；不能只测最初 30 秒 |
| 输入慢但帧率稳定 | 记录输入时间戳、逻辑消费点和呈现链路 | 查多帧队列、事件合并、网络等待、过长 tick；高 FPS 不能排除高延迟 |

## 5. 场景矩阵

至少选与目标问题有关的场景：冷启动/热启动、首次技能、最大敌人/弹幕/粒子、复杂 UI 与文本、大场景快速移动、连续切关、死亡重开、登录退出、音频切换、弱网重连、后台/前台、横竖屏/resize、资源加载失败、WebGL context lost 或 WebGPU device lost。

发布前覆盖低/中/高档目标设备、iOS Safari/Android 浏览器及实际 WebView 或微信宿主。记录不可测设备和未覆盖场景。
