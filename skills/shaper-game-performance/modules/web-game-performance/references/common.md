# 通用 Web 与游戏系统优化

矩阵各行采用「维度—信号—最佳实践—具体方案—验证/取舍」。按瓶颈选择，不把整张表变成无条件改造清单。

## A. 网页、启动与资源交付

| ID / 维度 | 诊断信号 | 最佳实践 | 具体优化方案 | 验证与取舍 |
|---|---|---|---|---|
| W01 首局关键路径 | 下载结束后仍久等，首帧不能输入 | 按可玩依赖而非全资源定义启动 | 启动代码/首关包优先；音频、后续关卡、装饰异步；记录阶段 mark | 冷/热启动到有效输入；避免首技能再补关键资源 |
| W02 JS 包与执行 | 下载小但 parse/eval 长 | 控制首屏代码和副作用 | tree shaking、按关卡拆包、延迟编辑器/调试工具；检查动态 import 的共享 chunk | coverage、parse/eval、首局可玩；过碎 chunk 增加请求 |
| W03 传输与 CDN | RTT 高、缓存缺失 | 正确内容类型/压缩和不可变版本资源 | Brotli/gzip 文本，CDN，内容哈希缓存；HTML/manifest 可更新，资源 immutable；跨域配置按实际需求 | Resource Timing/瀑布与缓存命中；不重复压缩已压缩纹理/音频 |
| W04 预加载与并发 | 预取抢首关，解码同时爆发 | 分阶段按优先级调度 | 限制下载/解码/上传各自并发，取消过期任务；prefetch 服从首关及内存预算 | 可玩耗时、峰值、弱网；并发最大不等于最快 |
| W05 缓存与离线 | 更新后白屏、包版本混用 | manifest 与缓存版本一致 | 原子切换资源版本、失败回退、容量/LRU；按需要使用 Service Worker | 更新/回滚/断网/配额满；不为普通项目强加 SW |
| W06 DOM 布局 | HUD 更新伴随 layout/paint | DOM 读写分批、仅更新变更项 | 移除逐帧强制布局；动画优先 transform/opacity，限制 layer；长列表虚拟化 | Performance trace、交互正确；额外合成层占内存 |
| W07 Canvas 与 DOM 桥 | React/Vue 每帧 render，桥接开销大 | 高频游戏状态留在引擎，UI 订阅低频摘要 | HUD 按值变化刷新，减少全局 store 扇出与每帧 setState | 框架 profiler 与 CPU；关键输入反馈不能低频 |
| W08 第三方与调试 | 埋点、广告、console 占主线程 | 生产开销有预算 | SDK 延迟加载、队列限量/批量、日志先判断级别再构造内容 | 生产构建 trace 与队列；保留必要错误诊断 |
| W09 存储与序列化 | 存档时长帧 | 大对象处理离开战斗热路径 | localStorage 小量配置；大存档用异步存储、增量编码，合适时 Worker | 存档延迟/失败恢复/一致性；异步 API 不代表序列化免费 |

## B. 帧循环、CPU 与输入

| ID / 维度 | 诊断信号 | 最佳实践 | 具体优化方案 | 验证与取舍 |
|---|---|---|---|---|
| C01 唯一主循环 | 多个 rAF/update 重复运行 | 让引擎拥有主循环 | 合并重复 ticker，切场景解除订阅，工具不再起第二渲染循环 | 每帧 update/render 次数，重开后稳定 |
| C02 时间步 | 帧率变化引起速度/碰撞变化 | 模拟与渲染按语义解耦 | 固定步长 accumulator、插值表现；限制单帧追赶步数和长 dt；明确积压/丢时间策略 | 30/60/120Hz 与后台恢复；联机确定性不能随意跳 tick |
| C03 任务分片 | 加载回调一次创建数千对象 | 用预算分帧，而非微任务堆积 | 节点创建/解析/上传队列按耗时让出下一帧；requestIdleCallback 仅非关键任务且提供 fallback | 长帧、完成延迟；Promise.then 链不能保证让出渲染 |
| C04 热路径分配 | GC 与尖峰重合 | 在证实热点后减少分配 | 复用向量/typed array、输出参数、稳定 buffer；去除循环内 map/filter/闭包/JSON | allocation profile、P99；可读性与池驻留权衡 |
| C05 数据布局 | 高频对象遍历 cache miss/访问杂乱 | 批量处理热点数据 | 活跃实体紧凑数组、SoA 或 typed array、增量更新；ECS 仅在能降低成本时采用 | CPU profile 与实体规模曲线；不无依据重写架构 |
| C06 场景图与变换 | matrix/world transform 时间高 | 静态层级少变、脏标记传播可控 | 冻结静态变换、减少无效父子更新、缓存查询结果 | 父子移动/缩放/剔除正确；动态节点不能错误冻结 |
| C07 Worker | 重计算堵塞主线程 | 分离纯计算与消息边界 | 寻路、解码、程序生成候选；Transferable 双缓冲，限制在途作业；能力检测 | 总延迟、消息复制/排队；小任务搬线程可能更慢 |
| C08 WASM | 数学/物理热点且跨边界频繁 | 大批次调用、明确内存所有权 | 合并 JS↔WASM 调用、复用 heap view，memory grow 后重建 view；先比较 JS | CPU、编译启动、堆峰值；WASM 不保证比 JS 快 |
| C09 输入与拾取 | pointermove 触发全场景 raycast | 输入消费与昂贵查询分开 | 缓存事件状态、每帧一次拾取，交互层过滤、空间索引；控制 passive/touch-action、pointer capture；笔划/节奏等保留所需事件样本 | 拖动、点击、滚动和延迟；需要 preventDefault 的监听不能设 passive，不能节流关键游戏输入 |
| C10 查询与排序 | 每帧 find、全量排序、距离开根 | 依赖变化时更新 | 实体索引、候选集、平方距离、局部排序或 dirty flags | 热点变化与玩法一致；索引维护亦有成本 |
| C11 GPU 同步/读回 | render-submit 内卡顿 | 避免主线程等待 GPU | 去掉生产逐帧 getError/getParameter/readPixels；必要读回降低分辨率/频率并使用可用的异步路径 | trace、结果延迟；诊断期有界查询可以保留 |
| C12 不变量与查表 | 同一三角函数/曲线在循环重复计算 | 先减少重复工作，再评估近似 | 把与实体无关的 sin/cos、矩阵和公共常量移到循环外；稳定曲线可测 LUT/插值并控制表大小 | CPU、误差、缓存成本；现代 JS 的 Math 函数可能更快，不能默认整数角度表足够精确 |
| C13 时钟域与动画相位 | 高刷新速度不同、恢复时动画跳变 | 明确游戏时间、单调实时时间与音频时间 | 装饰动画用统一时间相位或游戏时钟；可暂停动画累计有效 dt；物理用固定 tick，音频调度用 AudioContext.currentTime | 不同刷新率、暂停/慢放/恢复、音画同步；performance.now 是单调时间，不会替游戏自动扣除暂停 |

## C. 玩法、物理、AI 与动画

| ID / 维度 | 诊断信号 | 最佳实践 | 具体优化方案 | 验证与取舍 |
|---|---|---|---|---|
| G01 碰撞 broad phase | 候选对随对象数平方增长 | 空间与层级先过滤 | 网格/quadtree/BVH，collision group/mask，静态/动态集合分开；网格覆盖对象 AABB/查询范围，更新移动成员并去重候选 | 候选对、physics ms、大物体跨格/高速移动；结构更新有成本，只查中心格及固定 8 邻格不适合所有尺寸 |
| G02 刚体与 solver | 约束多、静止物仍活跃 | 形状简单、睡眠合理 | primitive/convex collider，减少无意义接触/迭代；CCD 只给高速小物体 | 穿透、堆叠稳定、手感；降低迭代是质量取舍 |
| G03 物理步进 | render 频率驱动物理乱跳 | 固定步长、插值渲染 | 按引擎推荐 tick、限制追赶；不要仅降 physics Hz 来掩盖热点 | 快速运动/低帧/回放；多人同步核对 tick 协议 |
| G04 AI 决策 | 所有敌人同帧重规划 | 时间切片与决策频率分层 | 不同实体错峰、预算队列、距离 LOD；感知与动作分开 | AI 响应、战斗难度；屏外敌人仍可能影响世界 |
| G05 寻路与导航 | 高频全图 A*、结果过期 | 局部重规划与复用 | 缓存有效路径、区域/层次导航、flow field 群体、Worker 作业取消 | 路径时延、障碍变化与过期结果；不能复用无效路径 |
| G06 群体与避障 | N² 近邻查询 | 邻域空间索引 | 网格邻域、限制感知半径、低频远处避障 | 聚集/瓶颈路线正确；不能让单位明显穿插 |
| G07 动画与骨骼 | animation/skinning 热点 | 采样、事件、表现分离 | 远处低频采样、少骨骼/权重、共享 clip、VAT/烘焙候选 | 姿态/事件/root motion；低频不应漏伤害帧 |
| G08 实体生命周期 | 弹幕生成长帧、重开后膨胀 | 活跃集与容量清晰 | 高频短命弹丸/命中特效适度池化；初始化全部状态，回收事件/引用；峰值后缩容 | 活跃/空闲数、峰值与稳态；不是所有对象都池化 |
| G09 粒子模拟 | CPU 粒子更新或上传重 | 模拟预算与屏幕贡献匹配 | 活跃数上限、生成率/寿命分层、GPU simulation 候选、局部空间模拟 | 粒子 update/GPU/过绘；转 GPU 后仍可能 fill bound |
| G10 休眠与逻辑 LOD | 屏外实体占 CPU | 表现裁剪与游戏逻辑独立 | 仅对允许休眠的系统降频，恢复补偿计时/状态；联机实体按协议处理 | 屏外战斗、任务/计时、恢复；不直接停止所有 update |
| G11 放置/离线结算 | 回前台补跑数小时 tick、计时器风暴 | 可聚合收益按区间或事件边界计算 | 存时间戳与结算状态；恒定产出用公式，有状态变化按事件段处理；收益上限及服务端校验依业务规则 | 与短时逐步模拟对照，检查系统时间变化、重连和重复结算；战斗/随机/非线性系统不能无依据直接乘时长 |

## D. 音频、联机与设备适配

| ID / 维度 | 诊断信号 | 最佳实践 | 具体优化方案 | 验证与取舍 |
|---|---|---|---|---|
| A01 音频解码与驻留 | 进入场景内存跳涨 | 短音效/长音乐分流 | 短音效有限预解码，长曲目按平台能力流式播放；限制同时解码 | 解码峰值与首次播放；压缩文件大小不等于 PCM 内存 |
| A02 声源与混音 | 爆炸密集时 CPU/破音 | 限制并发与优先级 | voice cap、远处剔除、同类合并、复用 buffer、释放 node/监听 | 听感、定位与混音 CPU；关键反馈保留 |
| A03 合成音效与调度 | 小音效下载占比高、播放时频繁创建上下文 | 合成、采样和流式音频按实际成本选择 | 短简单音效可用 oscillator/envelope 或预渲染后复用；复用受控 AudioContext，按用户激活策略 resume；一次性 source 用完清理，限制合成声部 | 下载、CPU、首声延迟和听感；复杂合成可能更耗 CPU，每次播放新建 AudioContext 不是优化 |
| N01 网络频率与载荷 | 高包率/解包长帧 | 模拟、发送、显示频率独立 | delta/量化/二进制、批量消息、兴趣区域；用 dirty 字段/版本或协议化比较生成 delta，保留全量恢复途径 | bytes/s、误差、编解码耗时；二进制编码不等于压缩，逐帧深度 stringify diff 可能更慢，先确认瓶颈再换协议 |
| N02 插值预测与回滚 | 画面抖、回滚长帧 | 按 RTT/jitter 设计缓冲 | 插值快照、自身预测与纠正；限制历史窗口与每帧回滚工作 | 延迟/纠正幅度/确定性；更深缓冲增加输入延迟 |
| N03 背压与重连 | send queue、快照年龄增长 | 有界队列及语义化丢弃 | 丢弃过期可替换状态、保留可靠事件；指数退避、重连恢复，停掉旧连接/计时器 | 弱网/断线恢复；不能丢交易/战斗关键事件 |
| M01 DPR/画质分档 | 高端屏低端 GPU，发热 | 分辨率按设备预算 | DPR cap、独立 renderScale，阴影/特效/LOD 分档；UI 保持清晰 | 真机清晰度、P99、GPU；内存容量不等于 GPU 档位 |
| M02 自适应质量 | 画质频繁跳变 | 平滑窗口、迟滞、冷却 | 持续超预算再降，稳定后慢升；分辨率/阴影/粒子分级而非每帧改 | 长时间稳定与 resize 分配；CPU bound 时降分辨率收益有限 |
| M03 后台与恢复 | 回前台追赶大量 tick/音效 | 明确暂停或后台策略 | visibility/宿主生命周期，暂停可暂停系统、重设时间基准、恢复资源状态 | 后台数分钟、音频/网络/计时；离线收益按业务处理 |
| M04 温控与能耗 | 数分钟后持续掉帧 | 持续体验预算 | 降无收益高刷新、限制非关键更新、轻量档、减少像素带宽 | 冷/热机各跑 10–30 分钟作为起点；时长按问题调整 |
| M05 resize/上下文恢复 | 横竖屏泄漏、恢复黑屏 | 重建路径显式且幂等 | 去抖尺寸变化、复用/释放旧 RT，context/device lost 时重建必要资源 | 反复 resize/丢失恢复、计数；不在每次变化重建整引擎 |
| M06 能力与设备分档 | UA/DPR 判断导致画质误配 | 能力检测、运行测量与用户选择结合 | 检测 backend/扩展/codec/输入能力，以保守默认和短时测量定档；deviceMemory/connection 仅作可选粗提示，缺失有回退 | 低端高 DPR、平板、WebView 与能力缺失；deviceMemory 不是省电状态，4g 不等于慢网，UA 不代表 GPU 能力 |

## E. 低动态效果与可访问交互

这些维度用于优化时保留可玩性，并控制替代 UI 的运行开销；不把完整无障碍改造强加给局部性能任务。

| ID / 维度 | 诊断信号 | 最佳实践 | 具体优化方案 | 验证与取舍 |
|---|---|---|---|---|
| X01 低动态效果 | 镜头震动/闪烁/装饰粒子造成不适或额外负载 | 用户偏好与性能档位独立 | 检测 prefers-reduced-motion 并提供游戏设置；减少非必要震屏、拖尾和背景动效，保留必要攻击/危险提示 | 偏好切换、GPU/CPU 与战斗信息；减少动画不能隐藏必要状态，也不能直接停止物理/计时 |
| X02 替代 HUD 与输入 | Canvas 信息不可访问、读屏播报/DOM 每帧更新、按键卡住 | 语义摘要按事件变化，输入方案保持等价 | 菜单使用可聚焦控件与可见焦点，关键事件有限 aria-live 播报，合并重复通知；支持键盘/触控/手柄及必要重映射，失焦清理按键状态；颜色之外补图形/文字线索 | 键盘和读屏、焦点返回、触控/手柄、DOM 成本；不要每帧播分数或无条件给整页 role=application，不统一用 60Hz 节流限制全部输入 |
