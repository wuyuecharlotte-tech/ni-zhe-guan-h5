# 测量与容量：按当前疑点选择

## 延迟

客户端拆分 DNS、连接、TLS、TTFB 和下载；服务侧区分接入等待、应用执行、下游往返与 SQL。仪表边界、时钟、样本与版本保持可比。请求超时缺少服务端标识时保留未归因，不由邻近日志强行解释。缓存命中耗时小不能证明整体响应快。

## SQL

从真实过滤、关联、排序、分页及行数分布查看执行计划；扫描、排序溢出、估算偏差、往返、锁竞争分别诊断。顺序扫描不总是错误，索引有写放大和构建成本。生产先用不执行语句的 EXPLAIN；EXPLAIN ANALYZE 会执行语句，读函数也可能产生写副作用。

## 预算

每实例上限 × 最大活跃实例数只是总连接/在途请求的粗略上界；加入代理复用、后台任务、其他服务、发布重叠和故障重连。SQL网关的 HTTP socket 数不等于 PG 连接数。分别确认平台限额、实际使用量和有效配置，回读配置才能确认写入生效。

响应对象、字符串、编码 Buffer、压缩缓存和瞬时拷贝均占空间；RSS、heap、外部内存和事件循环延迟一起解释。TTL 不限制条目数，短时稳定不证明没有泄漏。

## 反事实

将关键假设分别改变：数据量 ×10、热 key 比例变高、下游耗时 ×5、缓存清空、实例翻倍。判断瓶颈是否转移及预算是否仍有界。数字是敏感性分析，不是未经执行的压力测试结论。

## 负载证据

开放到达与闭环并发模型回答不同问题；闭环请求变慢会自动减少到达，可能掩盖过载。记录目标到达、实际发送、客户端丢弃、成功率、P95/P99和结束排空。确认发压机CPU/网络不是瓶颈。重试次数与首次结果单独记录。

单身份热读、多个身份、冷缓存、热点写、长时间运行分别说明覆盖范围。应用HTTP 200还要检查业务code/关键字段；排除未授权统计、初始化和交易副作用。需要生产压测时沿用任务授权和停止条件，本技能不自动发起压力流量。
